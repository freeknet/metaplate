This document is the current disposition of deferred work. A deferred item is
closed only when code, documentation, and verification evidence exist. A
provider recipe is not called certified merely because its runtime resembles a
local Node process.

| Streaming output | Decided against on 2026-11-01. Responses stay buffered so every one carries `Content-Length` and a strong `ETag` from the final bytes, which CDNs and `verifyImage`/`verify`/`verify-url` rely on; cards are 15 to 30 KB, so streaming would save almost nothing. The README states the rationale. |

## Release rule

The 0.7.0 release may claim documented recipes for the routes listed in
`deployment-evidence.json`, but only a route with complete artifact, build,
output, image, and metadata evidence may be marked `certified`. Socket status is `complete` for the captured historical 0.6.0 baseline, with every high/critical score-artifact alert matched to exactly one disposition. A fresh Socket query is required near release; `npm audit` passing does not substitute for that query.
